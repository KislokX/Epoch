## We measure phases by validation, not by features

A phase ends when an architectural claim stops being theoretical and becomes evidence.

### Phase 1 — Foundation validation *(in progress)*

Validate that the World behaves as a world: camera, pan, zoom, minimap, focus, boundaries.

The goal is not features. It is proving that the visible area is a window into a World with no
canonical size, and that the camera moves while the World does not.

Done when: the camera opens somewhere rather than everywhere, never shows the void, and the
minimap makes the unseen part of the World legible.

### Phase 2 — Experience validation

Validate the `Visit` contract end to end (ADR-0022).

```
Visit -> Camera -> Focus -> Reveal -> Experience
```

Reveal level 1 is enough: subtitle, occupants, focus, highlight. The point is the interaction
model, not its richness — the experience grows later without the contract changing.

Done when: visiting a Place feels like arriving somewhere, and nothing in it could reveal
something that does not exist.

### Phase 3 — Presentation validation

Build the **Launcher** as the second Experience Surface.

Not because the Launcher matters less than the World — because Visit validates the immersive
experience first, and once both surfaces exist over one Engine, "multiple Experience Surfaces"
stops being a diagram and becomes evidence.

Done when: the same Engine powers two surfaces with no logic duplicated between them.

The Launcher also became where the **crew** is managed (ADR-0023). That was not planned — it
followed from the Launcher being unable to state a true population, which turned out to be a
missing identity rather than a missing screen. Characters are the user's, portable between
Worlds, and edited over the vault file rather than in a parallel store.

Still open on this surface: the `animated_sprite` renderer, and exporting a World — which now
has to decide whether it carries the crew, since a character's artwork no longer lives inside a
World.

### Phase 4 — Someone actually thinks *(in progress)*

The Walking Skeleton: one Character, one Provider, one complete turn.

**Ollama first, deliberately.** No API key, no account, no bill, no network — the only provider
that can be true on a laptop with the wifi off. If the abstraction fits Ollama it fits the rest,
and every assumption about credentials had to be somebody else's problem from the start
(ADR-0007). Claude, GPT and Gemini are each a small implementation behind the same trait, plus
secure key storage.

Done: the canonical `Conversation` (ADR-0006 in its smallest honest form), the `Provider` trait,
the Ollama implementation with streaming, the registry, and a **measured** `CREW LINKS` in both
surfaces — ONLINE only when the Engine actually got an answer, listing the models the endpoint
really has.

Next: the turn reaching the World. `ActivityClass::Work` has existed since Presence and has never
once been true — nothing in Epoch has ever worked. Making it true is what this phase is for, and
the World already renders work differently from routine.

**Two things measured while building it, both of which change the product:**

- Probing a port whose packets are *dropped* rather than refused took **22.5 seconds** with a
  whole-call timeout set and doing nothing — the operating system's connect retry schedule runs
  before that clock starts, so only `timeout_connect` bounds the socket. That was a 22-second
  freeze on opening the Launcher, on any machine whose firewall drops. Now 0.7s, with a test that
  fails if it regresses.
- A **cold 20B model takes minutes** on its first turn while it loads from disk. The World must
  show her working rather than appearing frozen, and the default model should be whichever
  answers soonest — not the first one Ollama happens to list.

### Engine before life — a deliberate reordering (decided 2026-07-30)

Milestone 1's **Step 3** — routine-driven travel, the step its own roadmap calls *the first
wow* — is **not built**. `simulation.rs` has `Idle` and `Working` and no clock: the World is
inhabited but static.

That is now a **choice, not an oversight.** The remaining engine work — Trust Engine,
persistence, Composer, memory, MCP, cloud Providers, Project Root — comes first, and the World
is made to move afterwards.

This deviates from [Build From Life](docs/Build/Build%20From%20Life.md) rule 6 (*prioritise
visible life over invisible infrastructure whenever architecture permits*), knowingly, for one
stated reason: **behaviour and interfaces built on top of an incomplete engine would be built
twice.** Walking, routines, destinations and animation all read from state that persistence,
Trust and the Composer are about to reshape.

Rule 6 is not repealed — it is outranked, once, by a sequencing argument. It resumes the moment
the foundation is in place, and the first wow is owed.

### Then

Expand the Living World through authored content, assets and interactions — vitality before
expansion (`EXPERIENCE_CONSTITUTION.md`, XIX).

### Project Root — built (2026-07-31)

**Per World, on its card in the Launcher**, under the preview and above BOARD SHIP. A global
project root would be a lie the moment a second World exists, and ADR-0025 already says each
World has a real project root.

The folder picker is a **native dialog invoked from Rust**, not from the webview.
`<input webkitdirectory>` yields files and no path — browsers strip it deliberately. This does
not weaken ADR-0024: the frontend still never touches the filesystem, it asks the shell to ask
the user, and only the Engine reads what comes back.

Project Root answers *where does this World work*; Trust answers *what is this Quest allowed to
do there*. They stay separate (ADR-0025).

### Characters can actually work — built (2026-07-30 → 07-31)

The engine-before-life reordering, executed. Five steps, each a complete slice rather than a
subsystem:

- **Capabilities** (ADR-0008) — `read_file`, `list_files`, `find_files`, `write_file`,
  `edit_file`, `run_command`, `fetch_url`, `undo`. A `Descriptor` declares effects, reversal and
  parameters; **risk is derived from them, never declared**, so nobody can label a delete as
  low-risk.
- **Trust** (ADR-0009) — one pure `decide()` behind three orthogonal gates (mode · policy ·
  place), fail-closed. Modes are **Manual · Accept edits · Auto**; *Plan* was designed and cut
  before shipping — it was Manual with a different name, and a mode nobody can tell apart from
  another is a worse interface than one fewer mode.
- **The turn loop** — `NeedsApproval` and `NeedsCapability` are *stops*, not errors. Reaching for
  something never granted asks the user for it instead of dead-ending.
- **Project Root, `AGENTS.md`, Quest persistence** — per World, in the vault: context is a
  Quest's, and a Quest belongs to one World.
- **The Composer, for real** (ADR-0012) — budget, tiers, Provenance, and a Report per turn.

Two safety properties are structural rather than reviewed: `run_command` passes program and
arguments straight to the OS with **no shell**, so injection is not defended against — it is
inexpressible; and `fetch_url` resolves every address behind a hostname before connecting, with
redirects off.

**Four days were then spent on a character that would not use any of it** — and the write-up is
in [ADR-0012](docs/ADR/0012-context-composer.md)'s last amendment, because the lessons are about
composition, not about tools. Two: a projection that drops evidence falsifies the history it
replays, and **role is a transport decision that has to be measured per model**. Five plausible
causes were disproved by measurement before the real one was found, which is the argument for
the per-turn provider trace that now exists.

### Watching the work — built (2026-07-31)

Capabilities gained an opt-in `run_watched` (ADR-0008's closed open question), `run_command`
became spawn-and-poll, and the World gained a **Terminal** panel on the right: what the crew is
running, as it runs, for every character rather than only whoever is being spoken to.

Two defects fell out of building it rather than out of reading the code. `run_command`'s timeout
had never been enforced — `output()` waits, so a program blocked on input held the turn open
forever. And `fetch_url` lowercased the whole remaining document once per character inside a
`<script>`: every page tried until then had been a small README, and the first real page (1.3 MB,
mostly script) simply never came back. Both are the same lesson as Milestone 1's three defects —
**found by using the product, never by reading it**.

The palette also gained `--ep-warn`. It had no colour for failure at all, which is a quiet way of
building an interface that can only report good news.

### Next

1. **Finish the base.** *Done except one:* the dialogue resize trap is fixed (the grip is now
   kept reachable by measurement rather than by a guessed margin) and `run_command` has its
   `directory`. Still unverified in the running product: the capability-request flow, which
   became unreachable the day every capability started arriving ticked — it now needs somebody
   to untick one deliberately.
2. **Eyes.** `web_search` is **built**, on DuckDuckGo's HTML endpoint behind a one-method
   `SearchBackend`. Chosen because it needs no key, no account and no Docker — SearxNG would
   have asked the user to run a container, which the constitution rules out, and Brave needs the
   secret store that does not exist yet. The trait is the seam where those arrive; it is not
   speculative abstraction, it is one method at the exact place the replacement happens.

   Reading a page is not evidence, so `Outcome` gained **`sources`** alongside `evidence`: one is
   what a Quest produced, the other what it consulted, and a History that counted reading as
   achievement would be counting intentions (ADR-0025). They reach the conversation as *data*
   from the Engine and render folded under the answer — a surface that recovered URLs from prose
   would eventually cite something a character merely mentioned.

   Still ahead: pages that need JavaScript, which go to Playwright over MCP rather than into the
   Engine. A YouTube page fetched today contains no comments at all — they are loaded after the
   HTML, and a character should say so rather than invent them.
3. **Brains** (ADR-0027) — restructured 2026-08-01, when a user asked for Claude Code and Codex
   as a character's brain *and* as the agents they are. That does not fit ADR-0007: an agent owns
   its own loop. It also surfaced a commercial fact that decides the order — **a ChatGPT plan has
   no API**, so "use the subscription I already pay for" is only reachable through the vendor's
   own signed-in CLI.

   The reordering hinges on one thing: **an agent running its own permission prompt turns
   ADR-0009 into decoration.** A character set to `Manual` would be writing files while the
   dropdown said it asks first. So the MCP *server* — previously an interoperability nicety —
   became the security precondition for hosting an agent at all, and moved ahead of the second
   cloud Provider.

   | 5.2 MCP server | **the permission bridge.** Without it, step 6 cannot happen honestly |

   **3.2 shipped 2026-08-02.** The Engine half already existed; what was missing was that
   nobody could see it — `providers.toml` was a file you had to know about. The Connections deck
   is now a real deck rather than a sealed hatch, and building it surfaced one hole: `Backends`
   carried the reason its own file could not be read in a `#[serde(skip)]` field, so the reason
   never left the Engine. A surface showing the defaults with no way to say *these are not your
   choices* presents them as if they were. It now serialises out and is still never written to
   the file it describes, and never read back from one.

   Two decisions worth keeping: an id **cannot be renamed** in place — a character's brain names
   a backend by id, so renaming would repoint every one of them at nothing, silently — and
   *configured* is drawn as a separate fact from *online*, because collapsing them makes OFFLINE
   look like MISSING and the fix for those two is not the same fix.

   **3.3 shipped 2026-08-02.** Windows DPAPI into `vault/secrets.dat`, encrypted to the
   logged-in account (ADR-0026 amended with why, and with what it does *not* protect against).
   The type does half the work — `Secret` has no `Serialize`, so a Character Pack containing one
   does not compile — and building the store showed the other half was still open: a
   `get_backend_key` command returning a `String` would have undone the type guarantee at the
   IPC boundary. So there is no such command. The interface is told *that* a key exists and
   never what it is, and the field is empty on open because the value is not there to show.

   Proved on a real case rather than waiting for a hosted Provider: **Ollama behind a reverse
   proxy**, which is the same "machine under the desk" that made backend `id` and `kind`
   separate questions. Whole path exercised — type, store, provider, surface.

   One structural fix came with it: `Backends` now serialises through a private on-disk shape.
   IPC-only fields were being kept out of `providers.toml` by a `skip_serializing_if` per field,
   which works until the first field whose condition is sometimes false — and `keyed` was that
   field.

   **3.4 shipped 2026-08-02.** `Brain::{Model, Agent}` in the Kernel, carried by `Mind`
   (ADR-0027 amended with what building it decided). The choice that mattered: the kind is
   **which name is present** — `provider` or `agent` — rather than a `kind` field, so there is
   no migration and no line on every file that the user never has a reason to change.

   `provider()` returns an `Option`, which is the enum earning its keep: the three places that
   resolve a Provider now have to notice there might not be one, and say so instead of quietly
   using something the user did not choose. Agents themselves are still 6.x — the permission
   bridge comes first — so the Characters panel shows an agent brain as a cold instrument rather
   than an option in the model list.

   It exposed a defect worth naming. Loading a character validated its provider against a
   hardcoded `["ollama"]`. Correct when a provider id *was* a kind; wrong from the moment 3.2
   made backends configurable, and in contradiction with ADR-0023 — a backend named `desk` read
   as a typo, and a character carried to a machine where its backend is missing would have been
   refused rather than left unable to think. Gone.

   **4.1 built 2026-08-02 — not yet verified against the live service.** The account has no
   API credit, so no key exists to probe with. Everything below is what the code does; none of it
   has been confirmed by a real request, and the wire-shape assumptions are the part most likely
   to be wrong. Marked ◑ rather than ✔ until one turn actually completes.

   The first hosted Provider, and the point of it was the claim
   rather than the feature: `Provider` did not change. No new method, no variant, no flag —
   Anthropic is a translation behind the same trait, and nothing above it learned whose dialect
   is in use (ADR-0007, amended with what the build revealed).

   Four things had to be translated rather than forwarded: there is no system role in `messages`
   (hoisted to a top-level field), no tool role either (evidence replays as a user turn, because
   Epoch's record of a tool result is text with no id to pair a structured result with),
   `max_tokens` is required with a per-model ceiling (measured from the Models API, not guessed),
   and **the newest models reject `temperature` and `top_p` outright**.

   That last one is the one worth remembering. The obvious fix is a table of which models reject
   what — right the day it is written, quietly wrong after the next release. Instead the Provider
   sends what the character authored, and when the service refuses *and names a field*, drops it,
   retries once, and remembers for the session. Measured rather than tabulated, one extra round
   trip per model, and the turn succeeds instead of failing over a parameter the user cannot see.

   One canonical parameter it genuinely cannot honour: `context_tokens` asks a model to hold
   *less* than its window and this API has nowhere to say that. Not sent, and named as not sent —
   which is the case ADR-0026 said would be stated rather than pretended.

   **5.1 shipped 2026-08-02**, taken before 4.2 because OpenAI has the same blocker as 4.1 (no
   API credit) and MCP needs no account at all. JSON-RPC over a child process's stdio; every tool
   an outside server offers becomes an ordinary capability, judged by the same `decide()`.

   The finding is in ADR-0008's amendment: **MCP declares no effects**, and the hints it offers
   (`readOnlyHint`, `destructiveHint`) are a third party grading its own risk — the one claim
   ADR-0008 exists to make inexpressible. They are refused, and an outside tool is assumed to read,
   write, delete, execute and reach the network. So **every MCP tool asks the first time**. That
   is the correct experience rather than a degraded one: the Trust store remembers, so it asks
   once, and the user grants a named program a named permission.

   Servers are spawned on first use, never at startup, and the bridge outlives the capability
   registry — a registry is rebuilt every turn and a server is a process. Known limitation, said
   rather than left silent: `notifications/tools/list_changed` is not listened for, so a server
   whose tool set changes mid-session needs Epoch reopened.

   Deliberately not built: a proxy translating MCP into OpenAPI (mcpo). It exists because
   OpenWebUI speaks OpenAPI; Epoch speaks MCP natively from Rust, and adding a Python process is
   the infrastructure the constitution forbids the user to learn.

## Deliberately deferred

**[The Official Epoch Universe](docs/Milestones/Official%20Epoch%20Universe.md)** — the cast,
names, lore, cities, history, visual identity, music direction, NPCs, factions, symbols, logos
and the official default World Pack.

Not a renaming pass: the birth of Epoch's own identity. Deferred until the engine and the
product philosophy are mature enough to deserve it.

## Documentation

**Paused.** Documentation captures discoveries; it does not run ahead of them. A new
architectural document should exist because the running product taught us something we did not
know — not because we could imagine it in advance.
